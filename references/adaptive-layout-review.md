# 可适配的 Layout 制作与审阅规范

用于整理文字分镜、设计角色识别、输出导演审阅视频或处理反馈。依据用户提供的制作规范提炼；来源与页码见 [资料吸收记录](source-study-20261028.md)。文档里的项目命令是学习材料，只有当前用户要求或项目已采用的约定才成为该项目的执行要求。

## 先确定审阅用途，再选择格式

保留三个层次：

- **制作不变量**：镜号、时间、画面与实际工程对应；人物动作和摄影机动作可区分；关键行为可读；角色身份和跨镜状态一致；不同视频变体使用同一剪辑和帧表。
- **可调的审阅设计**：表格列数、信息区位置、字数、字体、尺寸、画幅、帧率、命名和状态标签。跟随项目与播放设备；不要为了套模板改构图、镜头节奏或已锁定参数。
- **原项目示例**：示例项目角色、身份色、无眼睛／无尾巴／去胸前斜条、24fps、16:9、八列表和1080p固定坐标。只在该项目明确采用时执行，不能据本资料改掉所有项目的 NARRATIVE_BOX_5 / COMBAT_BOX_4。

新任务没有交付约定时，可优先采用 CLEAN + DIRECTOR_REVIEW（文件可命名 REVIEW）+ 可编辑 .blend／所需资产 + 简短镜表与修改记录。已有交付约定继续沿用；用户只要单一输出时按其范围。DEBUG 按定位问题的需要提供，不与 REVIEW 混为一谈。仅分析或 Skill 编辑不生成 Layout 影片。模板见 [镜表和审阅配置](../templates/layout-review-plan.md)，可删减、合并和重排，不是新运行时 schema。

## 文字分镜保留语义，不锁死列数

一行通常对应一个实际镜头；长镜头可在一行分阶段，也可用同一父镜号下的阶段记录，不能把阶段误报成切镜。一个实际硬切应在剪辑表中有边界。经授权拆镜才使用子镜号。

| 信息 | 写到能执行的程度 | 可放在哪里 |
|---|---|---|
| 标识与时间 | 场／镜、源版本、秒数与帧区间；区分全片与镜内时间 | 表头、镜号／时长列 |
| 景别与机位 | 主体截幅、同框关系、前后层次、相对位置；焦距和感光面供执行核查 | 合并列或独立列 |
| 水平角度与视高 | 对谁的正／侧／背、摄影机相对眼高、俯仰；有变化写起止 | 两列或机位说明；执行数据可保留度数 |
| 画面内容 | 谁在何处、朝向谁，做了什么，往哪运动，落幅留下什么状态 | 主内容列／镜头卡 |
| 摄影机 | 固定，或运动类型、方向、开始／结束目标、速度与停顿；先后与同时分清 | 独立运镜列 |
| 声音与衔接 | 说话者、画外／旁白、必要音效、跨镜声桥；接什么动作、目光或结果 | 一列或拆分为声音与剪辑 |

景别按人物实际截幅判断，不把焦距当景别；多人镜说明主体及次要人物的截幅差异。画面左／右、角色自身左／右、世界方位分别标注。镜头角度与演员朝向不是同一字段。重要未定信息说明估计或待解决项；不填假精度，也不为非关键缺项阻塞已授权工作。

“八列：镜号、时长、景别与机位、角度、视高、画面内容、运镜、声音与衔接”是便于导演阅读的推荐视图。可以转换为已有项目表、卡片或结构化记录；没有依据时不增设必填 JSON 字段。

## 角色与可拍空间

复用同一角色资产／身份色及已批准轮廓；分别控制头部宽高、肩宽、体块和身高，不把全部角色做成一个模型的等比缩放。颜色由角色参考提炼并在项目中登记；材质基色一致不意味着受光后的每个像素必须相同。简模服务于身份、朝向、视线、动势和接触关系，不追求服装精细度。

胸线／腰线是**可选的截幅标记方案**，适合需要频繁核对中近景的几何角色。采用时将其绑定到真实的胸腰位置，环绕身体并随转身、倾斜、坐姿变化；不用随镜头移动的线伪造景别。头身比例特殊或非人形角色可用相应解剖／体块标记。是否保留在 CLEAN 由其身份／构图用途和项目约定决定；它们不等于调试轨迹。原图中短白条不等于环绕胸腰线。

只保留影响路径、尺度、遮挡、支撑、出入口和镜头层次的几何。树面、台阶和座椅要真的提供支撑，镜外人物继续保留世界状态。关键抓握、递物或接触可使用已支持的临时代理，并检查出现、连接、释放与收回；不声称无手／无脚模型已通过真实手脚接触验证。

## 审阅视频：画面、说明、对白各司其职

REVIEW 的目标是让导演定位“哪一镜、何时、发生什么、哪里要改”。建议包含：版本／镜号／时间码／帧率，常驻的本镜画面描述，简短景别与运镜，必要角色图例，独立同步对白。可用侧栏、上下栏、外置说明或其他布局；**保持实际镜头完整画幅和比例，不裁边、不拉伸，不让说明遮住关键行动**。原示例的左侧说明＋右侧画面＋下方对白是一种可选排版。

- 描述从该镜首帧到末帧覆盖全镜，切镜时同步更新；复杂长镜头可按阶段更新，完整叙述留在镜表。先写主体、关系、动作方向和落幅，避免只写“人物移动”。
- 文字层级优先保证画面描述，辅助技术信息其次。原资料的30–50字、7行、1080p母版和480p字号是起始参考。按真实目标播放尺寸检查；超长时精简或分阶段，不能一味缩小字体。描述不能补救画面本身无法辨认的动作。
- 对白注明角色；画外对白、旁白、必要音效与实际声音关系对应。按语义断句和实际对白／试读节拍同步，声桥可跨镜延续；没有对白则留空，不输出模板占位句。代理未做口型时不声称已完成口型同步。
- 有音轨则说明临时配音／音效；无音轨可在交付说明或同版信息区注明“无声审阅，含对白字幕”。不要为了加片头改变 REVIEW 与 CLEAN 的总帧数；确需前导片时另存，明确偏移。
- 时间码、全片帧号、镜内帧号使用明确标签。沿用已锁定 fps 和 timebase；不把原资料24fps下的帧位00–23用于其他帧率。非整数帧率需明确时间码规则。所有字幕和切点从同一帧表生成，注意现有接口的半开／闭区间换算。

CLEAN 去掉说明栏、对白字幕、时间码和调试线，恢复完整镜头画面；可保留已批准身份标记和承担动作语义的代理。REVIEW 只改变呈现与说明，不偷偷改机位、动作、时长。DEBUG 承载路径、接触点、阶段、方向等技术证据；不要用调试元素挤占常规导演审阅。

## 显示、反馈与验收

简模应有清楚的身份色、轮廓、接地和前后关系。原资料使用 Rendered 视口、Scene Lights／World、Combined 通道、禁用视口合成器及主题线框色；这是原工程的显示预设，不是所有 Blender 版本和工程的强制渲染配置。沿用项目引擎及已批准灯光，以最终相机编码画面为准。普通白盒不因学习摄影书就额外启动正式 Lighting Previs。

先在原速度完整看动作与信息，再定位切点、极值、接触和显露窗口；无播放能力就沿用 PLAYBACK_NOT_REVIEWED。小尺寸复核说明与字幕，核验无意黑帧／漏帧／停帧、角色跳位和 REVIEW/CLEAN 的同帧同步。镜表符合格式不等于叙事、表演或摄影通过。

反馈最少能定位“镜号＋时间码／帧段＋可见问题＋期望结果”，绑定版本、证据和修改范围，接入 [既有修正闭环](revision-and-review-loop.md)。可用待审／修改中／通过等适合项目的状态；技术通过、导演接受和最终定稿仍分开。按受影响依赖复核前后镜，不重新打开无关创作决策。命名只要求项目内可识别、同版可追溯，不强迫复制示例项目名或编号长度。
