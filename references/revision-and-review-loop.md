# 有证据的修正与增量交付

建立项目问题 ledger：问题ID、源版本、镜号／帧段、正式要求、实际编码画面证据、归因、允许通道、保护通道、候选次数、结果和未解决项。CAMERA / ACTION / PROP / SCENE / EDITING / LIGHTING 先归因，再修正。相机实验不顺带搬演员；跨模块修正用独立对照，并取得该字段授权。

导演反馈优先说清“希望观众在何时读到什么，当前哪个画面没做到”，再确定修改手段。镜号＋时间码／帧段＋问题＋期望结果是最小可定位反馈；状态可沿用项目用语，技术通过、导演接受和最终定稿分开。表格／版式适配见 [审阅规范](adaptive-layout-review.md)，摄影归因见 [摄影决策](cinematography-for-layout.md)；不因审阅排版改变而重做调度。

每个问题沿用用户次数上限；未指定时最多三次新候选。`reserve_attempt` 用持久化文件和独占锁记录，重命名版本或根因不能重置预算；崩溃预留仍计数。新增根因与授权范围确需另开实验时保留旧记录和新授权，不删除失败证据。锁文件残留时先核实没有运行者，再处理；不能自动删锁并并发写。

## 修改影响范围

- 相机局部区间：渲染该区间所属镜头，检查相邻切点。
- 人物、道具或场景状态持续变化：检查所有后续镜头，直到有证据的 reset；不能只改当镜然后让人物跳回。`invalidation` 的 persistent/reset_frame 显式表达这一点。
- 共享材质、灯光、World、环境：所有受影响镜头的旧像素无效；不能把旧光影拼入新版本。
- 字幕／审阅焦距文字：重编码对应审阅媒体，不重新渲染 Blender。
- 无法证明依赖完整：保守扩大范围，报告原因。依赖计算是调用方声明驱动，尚不能自动发现全部 Blender 数据关系。

复用旧媒体必须匹配源／场景修订指纹、区间、帧率、文件哈希与技术验收记录；不同未改镜头可以保留各自来源版本，但要列出混合来源镜表。不要把全局最新版本号贴到所有旧镜头并声称都重新制作。`verify_reuse` 验证声明与文件一致，仍须既有媒体 QA 核验真实帧数、帧率及解码。

## 视频证据

从最终编码文件抽起幅、落幅、动作事件前后、运动改变点、遮挡／显露窗口及切点两侧。`review_encoded.py` 提供基础半秒采样和显式事件窗口；遮挡事件需要作者标注或独立检测，不是自动可靠发现。检查原速度完整视频；慢放用于定位，不能代替正常速度判断。

分别记录：PLAN（计划）、NATIVE（Blender实际）、ENCODED（媒体）、VISUAL（画面）、DIRECTOR（叙事/艺术）、DOWNSTREAM（AI实测）。抽帧完成不等于 VISUAL PASS；没有播放能力就标明未观看。单纯亮度、运动量、屏幕占比不能算摄影质量总分。

布局校验至少包含：重要事件在画面中可读、道具不遮关键脸部、手物／支撑关系可识别、出画要求确实来自分镜、起落幅与关键动作不中断、时间轴和照明保护。缺陷无法证明改善时保留基线并列人工审核项。

新版修改使旧版定稿确认和交接卡对新版失效；历史交付保留并标明版本，不覆盖或删除。修改后的版本须再次明确确认定稿并完成最终 layout 交付，才可重新生成交接卡，见 [downstream-handoff.md](downstream-handoff.md)。

## 交付

只生成请求或已约定的组合；新项目未约定时采用 [审阅规范](adaptive-layout-review.md) 的建议组合。CLEAN 无字幕、镜号或调试字；REVIEW 使用完整镜头画面、本镜描述、镜号／版本／时间与必要对白，实际焦距等辅助信息按需呈现（变焦用实际变化值）。说明区与对白区相互区分，并在真实播放尺寸检查；不把审阅版当 AI 纯净参考。镜表保留镜号、时长、帧区间、切点、景别、摄影形式、焦距／感光面、主体动作、对白、变更与来源等适用信息，但可合并、重排和使用项目既有格式。相同源指纹绑定 .blend、媒体、帧表和证据。只重渲染确实失效的镜头，再按精确帧数拼接，核验总帧数和所有切点；不以快速转码代替缺失的画面修正。说明音轨状态不应给 REVIEW 单独增加片头导致同帧同步失效。
